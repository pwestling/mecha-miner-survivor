# events-simultaneous-ordering
#
# Rule under test: doc 10 § System phase ordering - "Simultaneous outcomes use
# documented stable ordering rather than collection or thread timing." For an
# event batch the keys are: tick, then explicit emission sequence. That is all
# of them.
#
# Two keys, because the emission sequence is per-tick global: CMP-SIM-003 issues
# it monotonically across the whole tick regardless of phase or emitter, so
# (tick, sequence) is a total order on its own. Neither the emitting system phase
# nor the emitting entity ID can discriminate any legal pair, so neither is a
# sort key. Both survive as recorded provenance, and the two facts that made them
# redundant are now checked instead of assumed:
#
#   1. Sequence is unique within a tick. A duplicate is an impossible input - a
#      defect in the issuer, not a tie - so it fails loudly rather than falling
#      through to a further key that would silently order it and hide the bug.
#      Enforced by EventOrdering.AssertTotalOrder: with a two-key comparator two
#      records sharing a tick and a sequence compare equal, so the adjacency scan
#      is itself the uniqueness check.
#   2. Phase agrees with sequence. Sequence is assigned at emission and emission
#      happens in phase order, so along ascending sequence within one tick the
#      phase must be non-decreasing. This is precisely what makes phase redundant
#      as a sort key, so removing the key without checking the fact would have
#      thrown the fact away. A system emitting out of phase order is a real
#      defect and this names it. Enforced by
#      EventOrdering.AssertPhaseAgreesWithSequenceWithinTick.
#
# This scoping is events only. Doc 20 § Boundary and tie ordering defines a
# separate five-key sort for damage instances - system phase, explicit attack
# sequence, target ID, source ID, then insertion sequence - and that is untouched
# by the rule above.
#
# Fixture: run session 0xE7E00001, tick 7, eight domain events across four system
# phases (3, 8, 10, 11), two emissions per phase. Sequence ascends 0 to 7 and
# phase is non-decreasing with it, so the fixture is a legal input. The events
# are appended in sequence order 5,0,3,6,1,7,2,4 - and that batch is also
# published reversed - so neither append order is the documented order and the
# sort cannot be a no-op.
#
# The previous fixture achieved that same non-no-op property by pairing phase 11
# with sequence 0 and phase 3 with sequence 1, deliberately disagreeing with
# phase order. Under the contract above that is an input the system cannot
# produce, so the old golden pinned an impossible state. Every observable field
# here is now a function of the sequence rather than of the append position, so
# the rows stay derivable once append order stops matching them.
#
# The stored phase numerals are correct by contract, not by coincidence: doc 10 §
# System phase ordering numbers a fixed fourteen phases and those numerals are
# stable normative identifiers. Renumbering is forbidden; a new phase takes the
# next unused number and a subdivision keeps its parent's. So a fixture may store
# 3, 8, 10, 11 and rely on their meaning.
#
# Every identity here - four emitters and the shared subject - is drawn from the
# OrdinaryEnemy partition, which begins immediately after Player. Player's
# capacity is the doc 20 § Scope and invariants invariant "exactly one player
# entity exists until terminal resolution", so the OrdinaryEnemy offset is 1 by
# simulation invariant and no doc 22 § Performance and capacity combat ceiling
# precedes it. The fixture asserts that computed containment rather than assuming
# it. An earlier fixture drew its subject from Pickup, which sits after all three
# doc 22 ceilings, which is why the literal 3830 was baked in here and would have
# made this ordering golden fail when the enemy-projectile ceiling moved.
#
# Derived by: the documented rule read off doc 10 and doc 20, computed in an
# independent Python reference before any C# ran, and cross-checked against an
# independent list sort in EventOrderingTests. Not by accepting whatever the
# buffer emitted.
#
